# CLI internals (`src/bin/`)

## Module map
- `index.ts`: entry and dispatch (`init | build | dev | page | fix`). Assigns `jsx`, `Fragment`, `raw`, `VERSION` onto `globalThis` before any compiled page is `require`d. `VERSION` is the placeholder `__SKRAPA_VERSION__`, replaced with the real version by `src/scripts/utils.ts` at bundle time. With no command given, it dispatches to `init` only when the cwd has no `skrapa.config.ts`/`.json`, no `tsconfig.json` and no `package.json`; otherwise it prints why and what to run instead (`fix` beside a legacy config; `dev`/`build`/`page`/`fix` or `init --force` beside a `tsconfig.json`; `npm run dev`/`npm run build` or `npx skrapa init` beside a `package.json`) and exits 1.
- One `cmd-*.ts` per command. Every command has the shape `Command<Result> = (overrides?: Skrapa.Config) => Result` (see `types.d.ts`). `build`, `dev` (through `build`) and `page` call `loadConfig` before anything else; `fix` calls it right after its config migration; `init` never does.
- `config.ts`: reading, merging and validating the config (see Config below). `jsx.ts`: build-time JSX runtime. `bundle.ts`: CommonJS bundler. `tag-parser.ts` + `rewrite-shell-imports.ts`: rewriting `src`/`href` on tags. `output-paths.ts`: "nothing may be written twice by different sources" rule plus the emitted-files manifest and `formatProblem`. `link-check.ts`: every local URL must name an emitted file. `format-html.ts`: dev-only pretty printer. `utils.ts`: `CONFIG_KEYS`, `DEFAULT_CONFIG`, `log`, `exe`, `isSkippedPath`, `isGlobalLink`, `versionBanner` (pads itself with a blank line above and below; its `npm unlink -g skrapa` hint shows only when `isGlobalLink(process.argv[1])`, i.e. a dev bin reached through a symlink outside `node_modules`).
- `isSkippedPath(root, file, exclude)` (`utils.ts`) is true for a path under a dot-dir (`.skrapa`, `.git`, `.github`), under `node_modules`, at or under one of `exclude`, or outside `root` (a `..` segment starts with `.`). The page walk, the dev source watcher, `fix`'s `collectTargets`, the stylesheet source check in `rewrite-shell-imports.ts`, `planPage`, and `src/scripts/sitemap.ts` all ask it, passing the skrapa root and the output and/or assets dir as `exclude`. Change it and all of them move together.
- Every module has a sibling `*.test.ts`. Add one when adding a module.
- `bin/index.js` is `.skrapa/src/bin/index.js` (tsc output of `src/tsconfig.json`) bundled by `bundle.ts` into one file: it walks the `require(...)` graph and inlines everything reachable under the entry's directory; Node builtins and npm packages stay as literal `require(...)`. Only `bin/`, `template/` and `skrapa.d.ts` ship, so the CLI cannot `require` sibling compiled modules. `cmd-build.ts` reuses the same bundler for a project's `<script src="...ts">` tags.

## The two roots
- **Skrapa root**: the cwd, the directory holding `tsconfig.json`. Nothing walks up to find it. Pages live under it, `.skrapa/` is written in it, and `output`, `assets` and `projectRoot` resolve against it.
- **Project root**: `path.resolve(skrapaRoot, config.projectRoot)`. Holds `package.json` (where `postbuild-skrapa` is looked up), `.gitignore`, `.github/`, and `skrapa.d.ts` (synced on every build).
- `InitContext.directory` (`types.d.ts`) is `{ skrapaRoot, projectRoot, output, assets }`, all absolute. `RewriteDirs` (`rewrite-shell-imports.ts`) spreads it, so its source root is `skrapaRoot`. `ResolvedConfig.projectRoot` is the string as written.
- The template's skrapa root is `template/src` (`TEMPLATE_SKRAPA_ROOT` in `cmd-init.ts`) with `"projectRoot": "../"`. The docs site's is `web/`, with the repo root as its project root.

## Build pipeline (`cmd-build.ts`), in order
1. `initContext`: `loadConfig` first, which prints every problem and exits before anything is written. Resolve the project root, then **overwrite `<projectRoot>/skrapa.d.ts`** from `<pkg>/skrapa.d.ts` (`path.join(__dirname, '../skrapa.d.ts')`) whenever contents differ. The compiled dir is `<skrapaRoot>/.skrapa`, scratch space: every build but a `skip-assets` rebuild removes it on process exit, failures included, so a standalone `build` leaves none behind and `dev` (whose first build runs in-process) removes it when it stops. Its rebuilds leave it alone, since the server needs tsc's incremental state and the manifest in it between saves. Creates the output dir. A missing assets dir is fatal only when `assets` is not the default.
2. `cleanOutput` (skipped for `skip-assets` rebuilds). Refuses if output is or contains the skrapa root, the project root, the assets dir or the cwd, and if output is inside the skrapa root and holds an `index.tsx` anywhere below it (`output: "docs"` beside a `docs/` page: the output dir is never searched for pages, and cleaning it would delete that page).
3. `tsc -p tsconfig.json --outDir .skrapa --rootDir .` with cwd the skrapa root. The tsconfig's own `outDir`/`rootDir` are overridden, so `about/index.tsx` always compiles to `.skrapa/about/index.js`.
4. Walk the **source** tree (the skrapa root, skipping directories where `isSkippedPath(skrapaRoot, dir, [output, assets])`) for `index.tsx`, and map each to `.skrapa/<rel>/index.js`. A compiled file that is missing is fatal and names the `.tsx` (the tsconfig's `include` left it out, or `noEmit`). `require` it, skip modules without an exported `Page` function. Zero pages is fatal.
5. Per page, position-dependent: call `Page()`; a bare element becomes `{ body }`. `rewriteShellImports(body, pageDir)` runs *before* splicing (page-relative `./x.css` resolves against the page dir). Find the nearest ancestor `index.html` shell, walking up to the skrapa root (none is fatal). Insert `<base href>` right after `<head>`, `head` raw before `</head>`, replace `<title>` text escaped. `applyTagAttrs` for `shellAttrs`. `rewriteShellImports(shell, shellDir)` on the shell *before* the body is spliced in. Splice body before `</body>`. Write pretty (dev) or dense.
6. Write the emitted manifest, run the output-paths collision check, copy assets, then run `link-check` last since it reads the output tree as deployed.

Fatality: collisions are fatal unless dev-mode-with-skip-assets and asset-only; link problems are fatal unless dev mode. Dev mode is detected by `process.argv[2] === 'dev'` or the positional `pretty`; `skip-assets` is another positional. These positionals are the internal dev-to-build protocol, not user flags.

## Dev server (`cmd-dev.ts`)
- Initial build is in-process, then `postbuildCommand(projectRoot)` (`npm run --if-present postbuild-skrapa`, only when `<projectRoot>/package.json` exists) runs synchronously with cwd the project root before the server listens; a failure logs and serves anyway. Every subsequent rebuild is a subprocess with cwd the skrapa root, so it reads the same `tsconfig.json`: `<node> <argv[1]> build skip-assets pretty --output .. --assets .. --base .. --linkCheckIgnore .. --projectRoot ..`, built by `rebuildFlags` from the *resolved* values of `BUILD_KEYS` (`output`, `assets`, `base`, `linkCheckIgnore` comma-joined and sent as `""` when empty, `projectRoot`) so flags and programmatic overrides survive, then `&&` the same postbuild command (npm finds the project root's `package.json` by walking up).
- On rebuild error, stdout is printed (tsc writes diagnostics to stdout). On success, **only lines containing the yellow ANSI code are forwarded**, so `log.warn` must stay stdout plus yellow or warnings vanish in dev.
- Source watcher: one recursive `fs.watch` on the skrapa root, each event filtered through `isSkippedPath(skrapaRoot, file, [output, assets])` (without that, every build's own writes to `.skrapa/` and an output dir inside the skrapa root retrigger it forever), debounced, full rebuild. Assets dir: its own watcher, single-file `cpSync` per event, filtered for editor temp files, checked against the manifest for collisions (refuses, no rebuild). It keeps `copied`, a set of every file the first build or the watcher copied out of assets; an event for a path no longer in assets removes what `staleAssetFiles` finds of it in that set from the output (skipping a file that is back in assets and any path the manifest says the build wrote), removes the directories that leaves empty, and reloads.
- The HMR `<script>` is injected at **serve time** for `text/html` responses, not written to disk. `/hmr` WebSocket handshake and frames are hand-rolled; other upgrade paths are destroyed.
- HTTP: strips the base prefix, percent-decodes, maps extensionless paths to `/index.html`, 403s path traversal.
- `EADDRINUSE`: `portHolder(port)` asks `lsof -iTCP:<port> -sTCP:LISTEN` for the PID, `ps` for its command line and `lsof -d cwd` for its working directory (null when neither tool can say). `portInUseMessage(port, holder)` is pure: the PID, where it runs (relative when under the cwd, absolute otherwise), the command line, and `kill <pid>` or `--port <number>`; with no holder, the one-line "already in use. Pass --port <number>" message. Printed line by line, then exit 1.

## Config (`config.ts`)
- The only file read is `./tsconfig.json` in the skrapa root (`CONFIG_FILE`), and the only key is its top-level `skrapa` (`CONFIG_KEY`). There is no `root` or `input`, nothing walks up from a subdirectory, and a `skrapa` key inherited through `extends` is not read.
- The key is **required**. `true` means every default (`readConfigKey` returns `{}`); an object sets fields; no key, or any other value, is a problem. A `tsconfig.json` without it is not a Skrapa project.
- Fields and defaults (`CONFIG_KEYS`, `DEFAULT_CONFIG` in `utils.ts`): `output` `dist`, `assets` `assets`, `port` 8080, `host` `localhost`, `origin` `''`, `base` `/`, `linkCheckIgnore` `[]`, `projectRoot` `.`. Every path resolves against the skrapa root.
- Parsed by `parseJsonc`, zero-dependency on purpose (never the project's `typescript`). `stripJsonc` blanks comments and trailing commas to spaces and keeps newlines, so its output is the same length as its input and every offset carries over; `insertSkrapaKey` (also in `config.ts`, used by `fix` and by `init`'s `keepTsconfig`) relies on that to edit the original text without losing comments. `isPlainObject` is exported for `init` and `fix`. `formatJson` writes JSON the way Prettier writes a tsconfig.json (four-space indent, an array holding no array or object inline when the line fits in 100 columns); `init` writes every tsconfig.json it generates through it, and `config.test.ts` checks it reproduces `template/src/tsconfig.json` byte for byte.
- Precedence, lowest to highest: `DEFAULT_CONFIG` < the `skrapa` key < `--flags` (`parseFlags`, one per `CONFIG_KEYS` entry; a flag with no value, last or followed by another `--flag`, is left out, and `flagsWithoutValue` reports it) < programmatic overrides. Flags and overrides are stripped of `undefined`/`null` so a hole cannot punch through; the file layer is merged as written, so `"port": null` is reported rather than filled.
- `readConfig(skrapaRoot = cwd, overrides?)` never exits and never writes. It collects every problem into one list and returns `{ config?, problems, skrapaRoot }`, with `config` present only when `problems` is empty (`init` uses it to read back the tsconfig it just scaffolded). `loadConfig(overrides?, skrapaRoot = cwd)` wraps it for commands: prints every problem and exits 1, else returns `{ config, skrapaRoot }`. `validateConfigKey(value)` checks a bare key value on its own, `true` included (used by `fix` before it writes, and by `cmd-init.test.ts` and `template-sync.test.ts`).
- Problems collected: a `LEGACY_CONFIG_FILES` file (`skrapa.config.ts`/`.json`) in the skrapa root (`fix` runs beside one only because it deletes the file before its own `loadConfig`); a `REMOVED_FLAGS` flag (`--root`, `--input`, `--ignore`, each with what replaced it; `--ignore` is `--linkCheckIgnore` now); a config flag with no value (`flagsWithoutValue`); a missing or unparsable tsconfig; a non-object top level; a missing `skrapa` key (the message says to add `"skrapa": true`); a `skrapa` value that is neither `true` nor an object; unknown keys; and anything `normalizeConfig` rejects.
- `normalizeConfig` is the single place values are coerced and validated: `output`/`assets`/`host`/`projectRoot` must be non-empty strings and `origin`/`base` strings; `port` a number or an all-digit string, integer 1..65535; `base` gets leading and trailing `/`; `origin` gets `http://` if scheme-less and trailing slashes stripped; `linkCheckIgnore` is an array of strings or a comma-separated string (a flag, or a dev rebuild), trimmed with empty entries dropped, and every pattern must start with `/`.
- `positionalArgs` drops config flags and removed flags *together with their values*, so `page About --input app` is a removed-flag error rather than a page nested under `app`. A flag with no value does not take the next flag as its value.

**Adding a config key** touches: `CONFIG_KEYS` and `DEFAULT_CONFIG` in `utils.ts`; `Skrapa.Config` in the root `skrapa.d.ts` (then `cp skrapa.d.ts template/skrapa.d.ts`); `ResolvedConfig` in `types.d.ts`; validation and normalization in `normalizeConfig` in `config.ts`; and `BUILD_KEYS` in `cmd-dev.ts` if a rebuild subprocess needs it.

## JSX runtime (`jsx.ts`)
- Elements are `RawHtml` instances branded `__jsx: 'element'`; `isElement` is `instanceof`. `raw()` wraps any string in one. Tests compare with `String(el)`.
- Children: elements pass through, arrays flatten recursively, `null`/`undefined`/booleans render as `''`, `0` is kept, everything else is escaped text.
- Attributes: emitted **as written**, so use `class`, not `className`. There is **no boolean shorthand**: `disabled={true}` emits `disabled="true"`; use `disabled=""` or omit. `style` accepts a string or an object (camelCase to kebab; `--custom` untouched). `undefined`/`null` attrs are dropped; other objects are `JSON.stringify`ed. `children`/`key` are skipped.
- A void element with children throws at build time.
- `escapeAttr` handles `& " <`; `escapeText` handles `& < >`. `unescapeAttr` is the inverse and is used by `applyTagAttrs` and `link-check`.

## Bundler (`bundle.ts`)
CJS only (tsc output). Only literal, `.`-prefixed specifiers are resolved (`rel`, `rel.js`, `rel/index.js`). Unresolved relative imports log an error but are **not fatal**; the literal `require` is kept. Bare specifiers are left as `require(...)`; when bundling for the browser this only warns, and the browser throws at runtime. The scanner skips comments, strings, template literals (entering `${}`), and regex literals.

## Path resolution, the most common bug class
- **Relative** (`./client.ts`) resolves against the directory of the file that wrote it (shell dir for a shell, page dir for page JSX). Never reaches `assets/`.
- **Root-relative** (`/style.css`) resolves from the assets dir first, then the skrapa root. A root-relative script resolves from the skrapa root's compiled tree.
- A stylesheet is only copied from source: `rewrite-shell-imports.ts` refuses any path where `isSkippedPath(skrapaRoot, file, [output, assets])` is true (the output or assets dir, a dot-dir, `node_modules`, outside the skrapa root) and warns "Stylesheet not found" instead, with the `/x.css` hint when a relative path's file is sitting in assets.
- `assets/` is copied over the output *after* pages render; a collision with a generated path fails the build because the asset would otherwise silently win. Assets are deliberately not recorded in the emitted manifest, or the dev watcher would refuse its own re-copy.
- Under a non-default `base`, `<base href>` governs relative URLs only. A hand-written root-relative link means the domain root.
- `link-check` compares by string equality against a walked set, never `fs.existsSync`, so it is case-sensitive on every OS. It skips `.js` files. Skipped references: another origin, a scheme URI (`data:`, `mailto:`, ...), a bare `#fragment`, and a path matching a `linkCheckIgnore` pattern (`globToRegExp`: `*` within one segment, `**` across segments, `?` one character, a trailing `/**` also matching the path itself), tested against the resolved site-absolute path and, inside the base, the path below it. A problem that is not case-only ends with the "Fix the reference so it names a file the build emits, or add its path to linkCheckIgnore" hint (`formatProblem` in `output-paths.ts`).

## Scaffolding and migration commands
- `init` locates the template as `path.join(__dirname, '../template')`, which resolves to `<pkg>/template` from the bundled bin. It refuses beside a legacy config file unless `-f`/`--force`. `chooseProjectRoot` decides new vs existing: `--new` is new; `--projectRoot <dir>` (read by `parseFlags`, checked by `projectRootProblem`; given no value, an error via `flagsWithoutValue`) is existing; both together is an error; with no TTY on stdin it is new; otherwise it asks "Is this a new project?" (`node:readline/promises`, default yes), then asks for the project root with `suggestProjectRoot(cwd)` (nearest dir at or above holding `package.json` or `.git`) as the default, re-asking until `projectRootProblem` (not a directory, or the cwd is not inside it) is clean.
  - `scaffoldNew`: `cpSync` the whole template into the cwd (`force` from `-f`). The skrapa root is `<cwd>/src`. An existing `src/tsconfig.json` is kept via `keepTsconfig`. Project root and output are read back with `readConfig` on the scaffolded tsconfig. Scripts are named `dev`/`build`.
  - `scaffoldExisting`: the skrapa root is the cwd. Copies `template/src` (minus its `tsconfig.json`) and `template/assets` into the cwd, then writes `existingProjectTsconfig(template tsconfig, projectRoot)` through `formatJson` (template compilerOptions; `skrapa` key with `output: "dist"`, `assets: "assets"`, `projectRoot`; `include` plus `<projectRoot>/skrapa.d.ts` unless the project root is `.`) unless one is kept. `writeUnlessPresent` (overwrites only with `--force`) puts `skrapa.d.ts` and `WORKFLOW_FILE` in the project root, the workflow via `existingProjectWorkflow(template, skrapaRoot from projectRoot)`. Scripts are `EXISTING_PROJECT_SCRIPTS` (`skrapa:dev`/`skrapa:build`).
  - Both: the project root's `.gitignore` gets whatever `gitignoreAdditions` says is missing from `<skrapaRoot>/.skrapa`, `node_modules` and the output dir, all as paths from the project root (the output is left out when it is outside the project root). `gitignoreAdditions` knows a leading or trailing slash names the same path and a slash-less line matches at any depth. `package.json` is created if absent; each script is added only when absent, as `skrapaScript(command, skrapaRoot from projectRoot)` (`cd <dir> && npx skrapa <cmd>`, JSON-quoted if the dir needs it, bare when they are the same dir); `engines.node` `>=24` if absent. `typescript` is installed (cwd the project root) only if neither `dependencies` nor `devDependencies` has it. Last, `npx skrapa dev` with cwd the skrapa root unless `--no-dev`.
  - `keepTsconfig` leaves an existing tsconfig as it is, except that one with no `skrapa` key gets one through `insertSkrapaKey` (the template's settings, or `true`), and warns what pages need from it.
- `page "<name>" [parent]` slugifies the name (lowercase, non-alphanumerics to `-`) and creates `index.tsx`, `index.html`, `style.css`, `client.ts` in `<skrapaRoot>/<parent>/<slug>/`. `planPage` refuses a parent that climbs out of the skrapa root (`..`) and a page dir `isSkippedPath` rejects (the output or assets dir, `node_modules`, a dot-dir). Refuses if `index.tsx` already exists. `page` tells `planPage` what exists, so a fresh page passes the link check: the shell links `/style.css` only when `<assets>/style.css` or `<skrapaRoot>/style.css` does (where `rewrite-shell-imports.ts` looks), and `index.tsx` gets a relative `./` home link, which `<base href>` resolves under any `base`, only when `<skrapaRoot>/index.tsx` exists.
- `fix` runs two idempotent migrations, in this order:
  - `migrateConfig(cwd)`: finds `skrapa.config.ts`/`.json` (both present is fatal, and so is no `tsconfig.json` beside it). `readLegacyConfig` loads it (`.ts` via `createRequire`, taking `default` or the module object; `.json` via `parseJsonc`). `splitLegacyConfig` sorts keys into carried (`CONFIG_KEYS`, plus `RENAMED_KEYS` under their new name: `ignore` becomes `linkCheckIgnore`), removed (`REMOVED_KEYS`, derived from `config.ts`'s `REMOVED_FLAGS` less the renamed ones: `input`, `root`) and unknown. `validateConfigKey(carried)` runs before anything is written (fatal). When the old `input` (default `src`) is not `.` and exists, `rebaseSettings(carried, input)` rewrites `output` and `assets` to reach the same places from inside `input` and sets `projectRoot` back up (`../dist`, `../assets`, `..` for the defaults). `insertSkrapaKey` adds the key as text (the settings, or `true` when there are none), first in the top-level object, via `stripJsonc` offsets so comments survive; with no settings and a key already there it writes nothing, and with settings it throws (fatal, printing the values to move by hand) if the tsconfig already has a key. Then the old file is deleted, it logs each rename, and it warns about dropped keys, a `.ts` config that read `process.env`, and, when the settings were rebased, the manual steps (`git mv tsconfig.json <input>/tsconfig.json`, `"include": ["**/*.ts", "**/*.tsx", "../skrapa.d.ts"]`, `outDir`/`rootDir` can go, run skrapa from `<input>/`).
  - Then `loadConfig`, then type renames (`renameTypes`) over `collectTargets(skrapaRoot, [output])` (walks with `isSkippedPath`, skips `skrapa.d.ts`): the old globals `Page`/`Props`/`PropsWithChildren`/`Tag`/`CSSProperties` become `Skrapa.*`, only in `:`, `as`, `satisfies` positions (generic positions are untouched since `<` is ambiguous with JSX); files declaring or importing their own type of that name are skipped.

## Cross-file couplings
- `ATTR` regex: exported from `rewrite-shell-imports.ts`, privately duplicated in `format-html.ts`. Change both.
- `VOID_ELEMENTS` (`jsx.ts`) and `VOID_TAGS` (`format-html.ts`) are separate sets and already differ (format-html lacks SVG).
- `init`'s kept-tsconfig warning (`keepTsconfig` in `cmd-init.ts`) lists the tsconfig settings pages need; keep it in step with `template/src/tsconfig.json` (see `managed-files.md`).
- `existingProjectWorkflow` string-replaces `npm run build` and `path: './dist'` in `template/.github/workflows/skrapa-pages.yml` and throws when either is gone; `cmd-init.test.ts` reads the real template to guard it.
- `TEMPLATE_SKRAPA_ROOT` and `existingProjectTsconfig` read `template/src/tsconfig.json`; `cmd-init.test.ts` checks its `projectRoot` resolves back to `template/`.
- `.tok-*` classes in `web/assets/style.css` pair with the tokenizer in `web/components/highlight.tsx`.
- `data-table.tsx` uses ARIA roles as its CSS selectors (`[role='table']` etc.); removing a role breaks layout.
