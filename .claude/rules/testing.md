# Testing

- `node:test` (`test`, `describe`, `before`, `after`) with `node:assert/strict`. Runner: `npx tsx --test "src/**/*.test.ts"`. Tests are colocated as `src/bin/*.test.ts`, plus `src/scripts/template-sync.test.ts` (`template/skrapa.d.ts` byte-identical to the root `skrapa.d.ts`, and valid `skrapa` keys in `template/src/tsconfig.json` and `web/tsconfig.json`) and `src/scripts/sitemap.test.ts`.
- `describe` names are `'<file path> - <functions>'` (a check that committed files stay in sync is `'<test file path> - <what> stays in sync'`; a real-build suite is `'<file path> - skrapa build, <situation>'`); test names are behavior sentences; a comment above a test names the regression it guards.
- `jsx()` returns a boxed element, so JSX tests wrap output in `String(el)` before `assert.equal`.

## `src/scripts/fixture.ts`, the harness for tests that need a real build
Used by `cmd-build.test.ts`, `cmd-dev.test.ts`, `cmd-page.test.ts`, `output-paths.test.ts` and `link-check.test.ts`.
- `runCli(dir, args)`: the same spawn for any command (`['page', 'About']`, `['fix']`); `runBuild` is `runCli` with `build --assets public` in front.
- `tempDir(prefix)`: a throwaway dir under the repo's `.tmp/` (gitignored). In-repo, not the system temp dir, so a fixture's own `tsc` resolves `@types/node` by walking up. The e2e project is `.tmp/project` (`TMP_DIR` in `src/scripts/utils.ts`, skrapa root `.tmp/project/src` as `TMP_SKRAPA_DIR`), a sibling of these, so no fixture ever lands inside it.
- `removeTempDir(dir)`: always the way to delete a `tempDir`, never a bare `fs.rmSync`. It removes the fixture, then `.tmp/` itself once nothing else is in it (`removeTmp` in `src/scripts/utils.ts`, which `dev.ts` also uses for `.tmp/project`), so a test run leaves no `.tmp/` behind. Test files run in concurrent processes, so `tempDir` retries when another one removes `.tmp/` between its `mkdir` and `mkdtemp`.
- `ensureBin()`: runs `buildBin()` (`tsc -p src/tsconfig.json` + bundle to `bin/index.js`) once per test process. Node runs each test file in its own process, so it rebuilds once per file that calls it.
- `runBuild(dir, args)`: spawns `bin/index.js build --assets public ...` with cwd `dir` (skrapa only reads `./tsconfig.json`) and `node_modules/.bin` on PATH, returns `{ status, output }`. Pass `['pretty']` to simulate a dev-mode build.
- `scaffold(fixture)`: writes a `tsconfig.json` built from `template/src/tsconfig.json` with its `skrapa` key replaced by `{ "output": "dist" }` and `include` by `["**/*.ts", "**/*.tsx"]`, plus `index.html` and `index.tsx` at the fixture root, so the one directory is both the skrapa root and the project root. Returns a `write(file, body)` helper. Fixture assets live in `public/`; the `--assets public` flag supplies that.
- `caseSkip`: probes case-folding once at import; use as `{ skip: caseSkip }` on tests that need two paths differing only in case.

## Patterns
- Build-once, assert-many: `before(() => { ensureBin(); fixture = tempDir(...); write(...); result = runBuild(fixture) })`, several `test`s on the one result, `after(() => removeTempDir(fixture))`.
- `cmd-build.test.ts` has pure `applyTagAttrs` tests plus real-build suites, each editing the scaffolded tsconfig through its local `writeTsconfig`: a config with problems (every problem named, nothing written: no clean, no `skrapa.d.ts`, no `.skrapa`); a project dir holding more than pages (`outDir`/`rootDir` ignored, nothing built from `node_modules` or a dot-dir); an output dir that holds a page (refused, page left in place); and a skrapa root inside a project root (the fixture's files moved into `src/` with `projectRoot: ".."`: `skrapa.d.ts` lands in the project root, output and `.skrapa` resolve against the skrapa root).
- `cmd-init.test.ts` tests the pure `init` helpers against the real template (`TEMPLATE_DIR`): the template's tsconfig sits in `TEMPLATE_SKRAPA_ROOT` pointing back at `template/`, `existingProjectTsconfig`/`existingProjectWorkflow` (including the throw when the workflow loses a replaced string), `suggestProjectRoot`/`projectRootProblem` against throwaway directory trees, `skrapaScript`, and `gitignoreAdditions`. The prompt itself is not tested.
- `cmd-dev.test.ts` covers `rebuildFlags`, `staleAssetFiles`, `postbuildCommand`, `portHolder` against a real listener (`{ skip: noLsof }` where `lsof` is missing), `portInUseMessage`, and one real `dev` run on a free port, in order: `postbuild-skrapa` ran before the server listened; a file and a directory deleted from `public/` while it runs leave `dist/` (polled, since `fs.watch` is asynchronous) while the built page and the postbuild file stay; `.skrapa` is kept until SIGINT stops it (last, since it stops the server).
- `cmd-page.test.ts` covers `slugify` and `planPage` (including that the global `/style.css` and the relative home link are written only when `globalStylesheet`/`homePage` say so), and one real run of `page` in a fixture with an empty `public/`, whose page then has to build at the default base and under `--base /repo/`.
- `config.test.ts` swaps `process.argv` via `withArgv` (argv[3+] is what the command sees) and calls `readConfig(dir)` against `os.tmpdir()` skrapa roots built by `tmpProject`/`withKey`. It never calls `loadConfig`, which exits.
- `isSkippedPath` and `isGlobalLink` are tested in `utils.test.ts`.
- `npm run test:e2e` is separate (`src/scripts/test.ts`): kills whatever holds port 8080, runs `src/scripts/dev.ts test` (build the bin, link, `init --new --no-dev` into `.tmp/project`, dev server from `.tmp/project/src`), polls HTTP, asserts, and leaves the server running so the site can be poked at. `.tmp/project` is removed when that server stops (Ctrl+C, or at once when a check fails), by `dev.ts`'s `exit` handler.
